# Language and script

Retrofitting this is expensive. Deciding it early costs almost nothing.

## Length

Interface strings expand by up to 40% from English into German and several other languages, and
contract sharply into CJK. Any layout that fits English exactly will break.

Never size a control to its label. Never place text in a fixed-width container without a defined
overflow behaviour. Test every component with a string 40% longer than the design copy.

Sentences assembled from fragments break in most languages because word order differs. Use whole
strings with named placeholders rather than concatenation.

## Script

Line height is not universal. Thai, Devanagari, and several other scripts have marks above and below
that collide at Latin line heights. Specify a per-script line height multiplier, or set the base
generously enough to hold the widest script the system serves.

The type stack needs a real fallback per script, chosen rather than inherited. A missing fallback
produces a system font that shares nothing with the display face and shows up immediately.

CJK needs different tracking and usually a different weight, since a font weight that reads normal in
Latin reads heavy in dense glyphs.

Never rely on italic for meaning. Several scripts have no italic and the browser will synthesise
something ugly.

## Direction

If the system serves an RTL language, direction is a foundation rather than a feature.

Use logical properties throughout. `margin-inline-start` rather than `margin-left`, `inset-inline`
rather than `left` and `right`. A system written with physical properties cannot be mirrored without
rewriting every component.

Icons that indicate direction mirror. Icons that depict an object do not. A back arrow flips, a
clock does not, and the list of exceptions needs to be published rather than guessed.

Numbers and Latin fragments inside RTL text stay LTR, and the bidirectional algorithm mostly handles
it, but test it rather than assuming.

## Formatting

Dates, numbers, and currency are locale-formatted by the platform rather than by string templates.
Publish which locale data source the system uses so every consumer produces the same output.

Tabular figures for anything aligned, in every script.

## Voice

The rules in `voice.md` do not all survive translation. Sentence case does not exist in every script.
Active voice is not always natural. State which voice rules are universal and which are per-locale,
and who owns the per-locale decision.
