# INTAKE — every question, asked once, at the start

kiln asks these in one batch before any work starts (user setting: questions up front only). The
answers are the brief; after the anchor pick the agent works to the end of the milestone without
asking again, and records every choice it made in `system/REVIEW.md`.

| # | Question | Answer |
|---|---|---|
| 1 | Name of the system and its packages (`<name>-tokens`, `<name>-react`) | |
| 2 | What it is for: the kind of product, who uses it, where (platform, device) | |
| 3 | References: images, sites or objects in `system/refs/`, and which one leads | |
| 4 | Lineage: the tradition outside web UI it borrows from (kiln proposes three if blank) | |
| 5 | Must never become (the failure the concept guards against) | |
| 6 | Themes: light, dark or both, and which is the base | |
| 7 | Backdrops: does the UI sit on plain surfaces, imagery or video | |
| 8 | Anchor pick: one of the 3–4 anchor variants rendered in `apps/lab/anchor/` (the only visual question) | |
